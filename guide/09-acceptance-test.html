# AC-IDT-01 (FR-IDT-01/02, BR-IDT-01/02)
Scenario: Đăng ký hợp lệ then tự đăng nhập
  Given email "a@x.vn" chưa tồn tại và password "Aa@123456"
  When POST /auth/register
  Then 201 trả user {status:ACTIVE, kycStatus:NONE} kèm accessToken+refreshToken
  And login lại bằng cùng credentials trả 200

Scenario: Password yếu bị chặn tại field
  When đăng ký với password "abc12345"
  Then 400 VALIDATION_ERROR, errors[].field = "password"

Scenario: Trùng email
  Given "a@x.vn" đã có
  When đăng ký lại
  Then 409 AUTH_EMAIL_TAKEN

# AC-IDT-02 (NFR-S-01, BR-IDT-03)
Scenario: Refresh rotation và reuse detection
  Given refresh token R1 vừa dùng đổi lấy R2
  When dùng lại R1
  Then 401 AUTH_TOKEN_INVALID và R2 bị thu hồi (cả family)

# AC-IDT-03 (FR-IDT-07, BR-ADM-04, UC-01 AF-3)
Scenario: ADMIN reset password — full chain
  Given user U ACTIVE, có refresh token R đang sống
  When POST /admin/users/{U}/reset-password {reason:"YC-88 CS Nguyễn"}
  Then 200 trả {tempPassword} + audit USER_RESET_PASSWORD (diff chỉ {reason, revokedRefreshCount})
  And mọi refresh của U bị revoked — dùng R → 401 AUTH_TOKEN_INVALID
  And U login bằng tempPassword → 200 nhưng password_must_change=true
  And U gọi GET /users/me trước khi đổi → 403 AUTH_PASSWORD_MUST_CHANGE
  And U đổi mật khẩu (POST /auth/change-password) → mọi API pass lại, password_must_change=false
  And tempPassword đã đổi mật khẩu rồi không login lại được

Scenario: Reset user SUSPENDED → 403 USER_SUSPENDED (BR-IDT-07, không phát sinh mật khẩu)
Scenario: Reset thiếu reason / reason 4 ký tự → 400 VALIDATION_ERROR field "reason"

# AC-IDT-04 (FR-HS-08, BR-IDT-08, US-IDT-05 — media foundation M-003, endpoints 64/65/66/67/68)
Scenario: Upload PUBLIC chỉ ảnh, đọc anonymous qua URL cố định
  Given user U đăng nhập
  When POST /files multipart {file: .png, visibility: "PUBLIC"}
  Then 201 {id, url: http://…/anphuc-public/fil_….png, visibility PUBLIC}
  And GET url (không token) → 200

Scenario: Tài liệu phải PRIVATE — presigned URL có hạn, người khác probe 404
  Given user U upload .pdf visibility PRIVATE → 201 (url null trong response)
  When user V (không phải chủ) GET /files/{id}/url
  Then 404 FILE_NOT_FOUND
  When U GET /files/{id}/url
  Then 200 {url: presigned có X-Amz-Signature, expiresAt ≈ now+900s}; hết TTL → S3 trả 403

Scenario: Sai định dạng / quá khổ / guest
  Given guest → POST /files 401
  And PUBLIC kèm file .pdf → 400 MEDIA_INVALID
  And ảnh 11MB → 413 MEDIA_TOO_LARGE

Scenario: ADMIN quản lý ảnh dự án (67/68)
  Given ADMIN gọi POST /admin/projects/{id}/images multipart ảnh
  Then 201 project_image {url, sortOrder = max+1}, GET /projects/{id} 🌐 trả `images` (cover = images[0])
  And DELETE /admin/projects/{id}/images/{imageId} → 204, object S3 bị xóa (GET url cũ ≠ 200)
  And imageId của dự án khác → 404 FILE_NOT_FOUND; DELETE /admin/projects/{id} cascade mọi ảnh
  And audit PROJECT_IMAGE_ADD / PROJECT_IMAGE_REMOVE (BR-ADM-01)

Scenario: Đăng ký + cọc đủ điều kiện
  Given user KYC APPROVED, không phải chủ, trước deadline
  When POST /auctions/{id}/registrations
  Then 201 PENDING_DEPOSIT, depositAmount = floor(opening*5%) (min 10tr)

Scenario: Chủ phiên không đăng ký được
  When owner listing đăng ký → 403 FORBIDDEN (BR-AU-05)

Scenario: Sau regDeadline → 410 AUCTION_REG_CLOSED

# AC-AU-03 (FR-AU-06/07/08, BR-AU-08..13)
Scenario Outline: Bid hợp lệ tăng đúng bước
  Given auction IN_PROGRESS, current=1 tỷ, step=10tr
  When bid <amount> → <result>
  Examples:
    | amount   | result                          |
    | 1009tr   | 422 BID_TOO_LOW min=1010tr        |
    | 1010tr   | 201 current=1010tr                |
    | 1050tr   | 201 (trên bước giá được chấp nhận)|

Scenario: Anti-snipe
  Given effective_end_at = now + 30s
  When bid 201
  Then auction.effective_end_at = now + 90s (idempotent 1 lần extend/bid)
  And audit AUCTION_EXTEND, event trả FE extended=true

Scenario: Race 2 bid cùng giá trị trong 10ms
  When gửi song song bid 1010tr từ user A, B (cùng registration ACTIVE)
  Then đúng 1 bid 201, bid còn lại 422 BID_TOO_LOW (lock current_price)
  And không có bid "mất": tổng số bid 201 == count rows

Scenario: Kết thúc 0 bid
  Given không bid nào, job tick qua effective_end_at + 60s
  Then state FAILED, listing RESERVED→LISTED, refund job hẹn +3 ngày làm việc, NTF-05

Scenario: Kết thúc có bid → AWARDED + order
  Then winner_registration leader, order PENDING với breakdown
       hammer + floor(hammer*1.5%) − deposit = payable, payBy=+24h

# AC-AU-04 (FR-AU-09, BR-AU-15..18, docs/04 F-03)
Scenario: Winner không trả trong 24h
  When job payBy đi qua
  Then order EXPIRED, registration FORFEITED, listing→LISTED,
       auction_privilege SUSPENDED, NTF, audit ORDER_FORFEIT
  And user đó đăng ký phiên khác → 403 AUCTION_PRIVILEGE_SUSPENDED

Scenario: Không tự trao giải nhì (BR-AU-18)
  Then không tồn tại mutation gán winner mới

Scenario: Suspend account bị chặn giữa phiên
  Given user có registration ACTIVE, auction IN_PROGRESS
  When PATCH /admin/users/{id} SUSPEND → 409 USER_HAS_ACTIVE_AUCTION (BR-IDT-05)
