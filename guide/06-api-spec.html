Status: In Review cùng Tech Lead — Author: Alex (PM) + BE Lead — Updated: 2026-10-10 — v1.4 (M-003 media foundation đã implement: SeaweedFS S3 + /files endpoints 64/65/66, ảnh dự án endpoints 67/68; object project thêm images; error code FILE_NOT_FOUND; supersede mock 20/21) — v1.3 (US-HS-01 bổ sung: endpoint 51 DELETE /admin/projects/{id} — hard delete + audit PROJECT_DELETE) — v1.2 (M-002/US-HS-01 đã implement: chốt hợp đồng endpoints 11/12/51 + Project schema §4.10, thêm message HOUSING_NOT_FOUND §5) — v1.1 (review pass: thêm endpoint 63 reset password + media download, ghi chú VALIDATION_ERROR/CONFLICT trùng code chung, bỏ duplicate DEPOSIT_REQUIRED) Nguồn chân lý: file này là hợp đồng FE↔BE để làm song song; backend implement qua @SwaggerApiDocument → OpenAPI live tại /api/v1/docs. Khi code lệch doc: doc đúng cho tới khi PM + Tech Lead đồng ý đổi và update cả hai. Base URL: {API}/api/v1 · Envelope success/lỗi, pagination, DomainError map: xem backend/README.md (không lặp lại ở đây).

1. Conventions ​

  • Auth: Authorization: Bearer <accessToken> (JWT RS256, 15m). Endpoint đánh dấu 🌐 = public (Swagger isPublic), 🔒 USER, 🛡 ADMIN. Guard role + ownership check trong use case.
  • Content-type: JSON; riêng upload multipart/form-data.
  • Pagination: offset ?page=1&limit=20 (max 50) → metadata {page, limit, total, totalPages}; bid feed dùng cursor: ?cursor=<lastBidId>&limit=50 → data {items, nextCursor}.
  • Idempotency: các endpoint tiền (POST /payments/intents, POST /orders/{id}/pay, POST /subscriptions/checkout, POST /auctions/{id}/bids) chấp nhận header Idempotency-Key (UUID, client sinh per attempt; server lưu 24h, retry trả lại response cũ).
  • Tiền/time: integer VND; timestamps ISO-8601 UTC; server gửi header X-Server-Time để FE hiệu chỉnh countdown.
  • Lỗi: luôn có error (ErrorCode), message tiếng Việt an toàn, errors[] khi validation field, details khi cần (minAcceptable, limit...). FE map theo error, không parse message.

4.11 Media foundation — endpoints 64/65/66/67/68 (🔒 files · 🛡 project images) — ĐÃ IMPLEMENT (M-003, backend/test/storage.e2e-spec.ts) ​

Hạ tầng: SeaweedFS S3-compatible (docker compose up seaweedfs) — bucket PUBLIC anphuc-public (anonymous GET, URL cố định) + bucket PRIVATE anphuc-private (chỉ presigned URL, hạn S3_PRESIGN_TTL_SEC default 900s). Object key = {fileId}{ext}.

Object file (response 201 endpoint 64): { id: "fil_…", url: string|null (chỉ PUBLIC), visibility: "PUBLIC"|"PRIVATE", originalName, mimeType, sizeBytes, createdAt }.

Endpoint 64 POST /files (🔒; multipart/form-data, field file bắt buộc, visibility optional default PUBLIC):

  • PUBLIC: chỉ ảnh image/jpeg|png|webp|gif (tài liệu phải PRIVATE); 400 MEDIA_INVALID nếu mime nằm ngoài whitelist.
  • PRIVATE: ảnh hoặc tài liệu (application/pdf|msword|officedocument...).
  • Kích thước: ảnh ≤ 10MB, tài liệu ≤ 25MB → 413 MEDIA_TOO_LARGE (multer limits.fileSize + filter).
  • → 201 file; audit không ghi (chưa phải mutation domain công khai).

Endpoint 65 GET /files/{id}/url (🔒): PUBLIC → { url, visibility, expiresAt: null } cho mọi user đăng nhập. PRIVATE → chỉ chủ sở hữu hoặc ADMIN, { url: presigned, expiresAt: ISO }; người khác / id không tồn tại → 404 FILE_NOT_FOUND (chống probe).

Endpoint 66 DELETE /files/{id} (🔒 owner/ADMIN): → 204, xoá row + object S3. Không owner/không tồn tại → 404 FILE_NOT_FOUND. File đã gắn project_image → không xoá trực tiếp (phải qua 68; row ảnh FK cascade ngược lại).

Endpoint 67 POST /admin/projects/{id}/images (🛡; multipart field file, chỉ ảnh PUBLIC): → 201 project_image { id, projectId, url, sortOrder, originalName, mimeType, sizeBytes }, sortOrder = max+1; 404 HOUSING_NOT_FOUND khi dự án không tồn tại; audit PROJECT_IMAGE_ADD.

Endpoint 68 DELETE /admin/projects/{id}/images/{imageId} (🛡): → 204, xoá stored_object + object S3 (không để orphan PUBLIC); imageId không thuộc dự án/không tồn tại → 404 FILE_NOT_FOUND; audit PROJECT_IMAGE_REMOVE. DELETE /admin/projects/{id} (51) cascade mọi ảnh kèm object S3.

Seed media (dev, không qua API): npm run db:seed:media — PNG gradient placeholder cho dự án chưa có ảnh (idempotent). Cần sau mỗi lần npm run test:e2e (suite wipe DB): db:seed:projects → db:seed:media.

6. Quy tắc thiết kế BE phải tuân (trích, để reviewer đối chiếu) ​

  1. Controller mỏng, không try/catch bắt DomainError — filter lo.
  2. Validation DTO bằng class-validator đúng ràng buộc §FR docs/02 (whitelist đang global).
  3. Mọi endpoint mutation của USER phải ownership check trong use case (404 khi không phải owner — tránh probe tồn tại).
  4. Public GETs cache-control: listing/auction s-maxage=30; bids no-store.
  5. Break-change policy: thêm field OK; đổi tên/kiểu → version endpoint, không đổi âm thầm (FE đã mock).
