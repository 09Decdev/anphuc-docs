SC-41 — Queue duyệt KYC ​

ADMIN SLA 48H Route: /admin/kyc Nguồn: docs/05 §3 SC-40..49 · docs/02 FR-KYC-04/05 · docs/03 UC-02 · docs/08 BR-KYC / BR-ADM · docs/06 endpoints 47/48

Ai xem màn này: Quản trị viên (guard ADMIN 🛡) — người duyệt hồ sơ xác minh CCCD thủ công (v1 không có API 1411/dữ liệu dân cư). Mục đích: xử lý queue PENDING đúng SLA 48h với thao tác tối thiểu: bảng sort quá-hạn-trước → mở drawer đối chiếu → Approve/Reject (reject bắt buộc reason 10–500 ký tự, hiện nguyên văn cho user). Mỗi quyết định = toast + audit log. Ví dụ số dùng trong bản vẽ: "bây giờ" 10/10/2026 14:31 (GMT+7) · queue 5 hồ sơ PENDING · 1 quá hạn (LE VAN CUONG, nộp 08/10/2026 08:12, deadline 48h = 10/10 08:12 → quá 6h) · hồ sơ mở drawer: ky_01J9X2K8M2 của LE VAN CUONG, CCCD 031088456721, DOB 21/03/1988 (38 tuổi).

Chú thích hành vi (trace: docs/03 UC-02 · docs/02 FR-KYC-04/05 · docs/08 BR-KYC/BR-ADM)
  1. 1DataTable server-side `GET /admin/kyc-queue?status=&page=` (endpoint 47): filter tab = query `status` (PENDING/APPROVED/REJECTED), phân trang offset 20/trang, URL sync (shareable giữa 2 admin). Sort mặc định: quá SLA trước → `submittedAt asc` (cũ nhất xử lý trước) — đúng FR-KYC-05. Search debounce 400ms. FR-KYC-05 docs/05 §3 SC-40..49
  2. 2SLA badge `wf-sla` tính từ `slaReviewBy` (docs/06 §4.7 = submitted + 48h) so với GIỜ SERVER: `ok` (còn hạn) · `soon` (≤ 8h — vàng, sắp đến hạn) · `over` (đỏ nhấp nháy — quá hạn). Hàng quá hạn tint nền danger-soft; count > 0 → banner đỏ đầu trang, đồng bộ Dashboard SC-40 (FR-STAT-01). BR-ADM-03
  3. 3Tuổi hiển thị = server đã check ≥18 lúc nộp (BR-KYC-01, `KYC_UNDERAGE` 422 chặn từ trước) — admin chỉ nhìn, không phải tự tính. CCCD hiển thị đủ 12 số cho admin (permission: ADMIN ✅ xem — docs/08 §9); với màn user khác vẫn mask. BR-KYC-01 NFR-S-05
  4. 4Click "Xem ▸" → mở drawer phải (mục 2) — không điều hướng trang, giữ nguyên vị trí bảng + filter; ESC/click nền đóng drawer. Row vừa xử lý xong biến mất khỏi tab PENDING ngay (optimistic + refetch). docs/05 §3
  5. 5Export CSV theo filter hiện hành (`GET /admin/export/{entity}?filters`, max 50k dòng). Mọi mutation màn này (approve/reject) → toast + audit log (KYC_APPROVE/KYC_REJECT — actor, diff redact PII, ip, trace_id). FR-STAT-02 BR-ADM-01
  6. 6Lần nộp/30 ngày (BR-KYC-06: tối đa 3 application/30 ngày rolling): cột này giúp admin biết reject lần này còn đường lui hay không — `3/3` hiện warn "lần cuối": nếu reject, user hết quyền nộp lại trong 30 ngày (hướng dẫn liên hệ CS). Hover xem lịch sử application cũ trong drawer. BR-KYC-06

7. Responsive — desktop-priority ​

Ghi chú responsive (không vẽ frame mobile đầy đủ)
Màn duyệt KYC là desktop-priority (docs/05 §1.2): drawer cần không gian đặt 2 ảnh CCCD cạnh checklist. Dưới 1024px: rail collapse hamburger; bảng scroll ngang (sticky cột "Hồ sơ" + cột action); drawer chiếm full-width từ phải. Dưới 768px ảnh CCCD xếp dọc, checklist ngay dưới ảnh, 2 nút quyết định sticky đáy. Mobile chỉ khuyến cáo cho thao tác KHẨN (hồ sơ quá hạn) — không phải ca làm việc chính.
