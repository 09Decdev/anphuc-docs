SC-02 — Danh sách tin NOXH ​

Route: /nha-o-xa-hoi Nguồn: docs/05 §3 SC-02 · docs/03 UC-03 · docs/02 FR-HS-06 · docs/08 BR-PKG-06

Ai xem màn này: Guest + Thành viên đang tìm mua — vào từ search trang chủ (SC-01), link SEO, hoặc link chia sẻ (URL chứa sẵn filter). Mục đích / cảm xúc thiết kế: công cụ tìm kiếm nghiêm túc — filter rõ, kết quả đếm được, không quảng cáo chen ngang. URL là trạng thái: copy link gửi nhau phải ra đúng kết quả. Ví dụ số dùng trong bản vẽ: 137 tin · 7 trang · căn CT2-A18.05 NOXH HP-380 · 72 m² · 1.250.000.000 ₫ · filter giá 1–1,5 tỷ, diện tích từ 60 m².

Chú thích hành vi (trace: docs/05 §3 SC-02 · docs/02 FR-HS-06 · docs/06)
  1. 1URL-sync toàn bộ query: mọi thay đổi filter/sort/page ghi lên query string (replaceState, debounce 300ms) — link copy được, share được, back/forward trình duyệt hoạt động. Param khớp API: `q, projectId, priceMin, priceMax, areaMin, areaMax, sort, page, limit`. FR-HS-06 docs/06 §4.1
  2. 2Filter validate phía FE trước khi gọi: giá min lớn hơn giá max → field-error đỏ "Giá tối thiểu phải nhỏ hơn giá tối đa", không gửi request (BE ignore cặp vô hiệu — UC-03 EF-2). Ô "Dự án" là select search-as-you-type từ `GET /projects?q=`. UC-03 EF-2 docs/06 §3 endpoint 11
  3. 3Sort mặc định = newest (`listedAt desc`). `featured` = quy tắc tĩnh: VIP trước rồi newest — không AI; card VIP có badge ★ + viền accent. Đến từ SC-01 qua link "featured" thì preselect. BR-PKG-06 FR-HS-06
  4. 4Đếm kết quả lấy từ `metadata.total`. Chip filter đang áp dụng (có ✕) hiện trên đầu grid — bấm ✕ gỡ 1 filter và cập nhật URL. Badge trạng thái tin: Đang bán = LISTED (xanh), Sắp đấu giá = RESERVED (xám) — màu theo enum docs/07 §3. docs/06 §1 docs/07 §3
  5. 5Tin RESERVED có phiên: card hiện thêm dòng giờ mở phiên; click card vẫn vào SC-03 (từ đó link sang SC-06). Chỉ tin LISTED/RESERVED/SOLD xuất hiện public — DRAFT/IN_REVIEW/REJECTED không bao giờ lộ. FR-HS-07
  6. 6Pagination offset `page/limit`; đổi trang scroll lên đầu grid; `page` vượt totalPages → BE trả rỗng, FE redirect về page cuối hợp lệ. Public GET có cache `s-maxage=30` — số liệu có thể trễ tối đa 30s, chấp nhận được. docs/06 §6.4

Chú thích mobile
  1. 7Rail trái biến thành nút "Bộ lọc (N)" — N = số filter đang áp, cạnh nút sort. Drawer mở từ đáy (bottom sheet) trên mobile thật; wireframe vẽ dạng panel full-width. Chip filter hoạt động y hệt desktop (bấm ✕ gỡ ngay, không cần mở drawer).

3. Loading — skeleton grid ​

TRẠNG THÁI: LOADING (đổi filter / sang trang)
Filter rail giữ nguyên giá trị đang chọn (không skeleton); grid mờ đi + skeleton khi refetch. Đổi trang: skeleton đủ 20 ô tránh nhảy layout.
Chú thích
  1. 9Skeleton card dùng chung component với SC-01 (mục 3). Request có cache 30s nên lần vào lại thường instant — skeleton chỉ hiện khi miss cache hoặc đổi query. docs/05 §1.4 docs/06 §6.4

6. Checklist designer khi dựng Figma cho SC-02 ​

  • [ ] Đủ layout: desktop (rail 220px + grid 3 cột) / tablet 768 (rail thu thành drawer, grid 2 cột) / mobile 360 (1 cột + bottom sheet filter)
  • [ ] Đủ 4 trạng thái: Loading skeleton · Empty + clear filters · Error + traceId + Thử lại · Data
  • [ ] Filter rail đủ control: search text, select dự án (search-as-you-type), 2 ô giá min/max, 2 ô diện tích, checkbox phòng ngủ, select sort (4 giá trị)
  • [ ] Card tin đủ biến thể: ★ VIP + viền accent / badge Đang bán (LISTED) / badge Sắp đấu giá (RESERVED + giờ mở phiên)
  • [ ] Chip filter đang áp dụng ( removable ✕ ) vẽ cả trên desktop lẫn mobile; count preview trên nút "Xem N tin" của drawer
  • [ ] Validate FE: giá min lớn hơn giá max → field error đỏ, không gọi API
  • [ ] Copy đúng docs/06 §5; tiền 1.250.000.000 ₫; ngày dd/MM/yyyy HH:mm + GMT+7
  • [ ] Không emoji icon trong UI production (🔍/⚙ trong wireframe là placeholder vị trí)
  • [ ] Accessibility: label cho mọi input filter; drawer trap focus + đóng bằng Esc; pagination có aria-current; kết quả có aria-live khi refetch
