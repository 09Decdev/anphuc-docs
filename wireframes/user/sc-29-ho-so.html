SC-29 — Hồ sơ cá nhân ​

ƯU TIÊN THẤP (MS1) Route: /ho-so Nguồn: docs/05 §3 SC-29 · docs/02 FR-IDT-04/05/07 · docs/08 BR-IDT-01/02 · BR-ADM-04

Ai xem màn này: Thành viên đã đăng nhập (guard USER 🔒) — tự sửa hồ sơ của chính mình. ADMIN không sửa hộ user qua màn này (docs/08 §9: "Sửa hồ sơ mình — ADMIN ⛔, xử qua ops"). Mục đích: sửa thông tin liên hệ hiển thị (tên / SĐT / avatar) và đổi mật khẩu. Hai nguyên tắc bất biến: email READ-ONLY (định danh đăng nhập duy nhất) và mật khẩu mới phải qua rule BR-IDT-02. Ví dụ số dùng trong bản vẽ: NGUYEN VAN A · email nguyenvana@example.com · SĐT 0912 345 678 · KYC APPROVED 08/10/2026 · gói VIP_STANDARD đến 07/11/2026 · "bây giờ" 10/10/2026 14:35 (GMT+7).

Chú thích hành vi (trace: docs/02 FR-IDT · docs/08 BR-IDT · docs/06 §5)
  1. 1Form nạp từ `GET /auth/me` (endpoint 5); lưu bằng `PATCH /users/me` (6) partial — FE chỉ gửi field user thực sự đổi. Validate onBlur + onSubmit, message tại field. FR-IDT-04 docs/05 §1.5
  2. 2Email READ-ONLY ở CẢ HAI tầng: UI khóa input + server từ chối (PATCH chỉ chấp nhận fullName/phone/avatarUrl; field thừa → 400 do global whitelist). Lý do nghiệp vụ: email là định danh đăng nhập unique — đổi email tự do sẽ phá anchor KYC/audit và mở đường chiếm tài khoản. v1 không có self-service đổi email cũng như quên mật khẩu (CS + ADMIN reset — UC-01 AF-3). BR-IDT-01 FR-IDT-04 docs/02 §5.1
  3. 3Avatar — contract còn hở (flag cho PM): `PATCH /users/me` nhận `avatarUrl`, nhưng `POST /media/upload` (endpoint 20) mới có kind `listing_photo|listing_doc|kyc_doc` — CHƯA có kind avatar. Wireframe vẽ cả 2 đường (nút upload + ô URL); khi BE chốt kind mới thì bỏ ô URL. Không tự mock API chưa có. FR-IDT-04 FR-HS-08
  4. 4Lưu thay đổi: 4 trạng thái nút default / loading (disabled) / success (toast ok "Đã lưu thay đổi hồ sơ") / error (field errors từ `VALIDATION_ERROR` — `errors[]` theo field, copy chuẩn docs/06 §5). "Hủy bỏ thay đổi" reset form về data server, hỏi xác nhận khi form dirty. docs/05 §1.3
  5. 5Đổi mật khẩu `POST /users/me/change-password` (7): mật khẩu cũ sai → 401, field error nguyên văn "Email hoặc mật khẩu không đúng"; thành công → thu hồi toàn bộ refresh token của các phiên KHÁC — toast phải nói rõ "các thiết bị khác đã đăng xuất" để user không hoảng. FR-IDT-05 docs/06 §5
  6. 6Strength meter là hint FE (4 nấc: yếu/trung bình/mạnh/rất mạnh), không thay thế validation server — server mới là chốt theo BR-IDT-02 (hash argon2id). Mật khẩu mới trùng mật khẩu cũ → FE cảnh báo sớm, server 400. BR-IDT-02
  7. 7Icon 🔒/👁/✎ trong wireframe là placeholder vị trí — production dùng icon set thật, không emoji. docs/05 §7
  8. 8Cột trạng thái tài khoản chỉ đọc, nguồn `GET /auth/me`: KYC status (NONE/PENDING/APPROVED/REJECTED), gói ACTIVE + endsAt, `auction_privilege` (GRANTED/SUSPENDED). SUSPENDED quyền đấu giá → badge danger + link giải thích BR-AU-16; tài khoản SUSPENDED (BR-IDT-07) → banner đầu trang "Tài khoản bị tạm ngưng — liên hệ CSKH", form disabled. docs/07 §2.1 docs/08 §9

5. Checklist designer khi dựng Figma cho SC-29 ​

  • [ ] Không emoji icon trong UI production (🔒/👁/✎ là placeholder vị trí)
